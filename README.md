# โมดูลบุคคล — Mockup สำหรับ UAT

ระบบ `smartssolar-tools.duckdns.org` · บริษัท สมาร์ท เอ็น คอนซัลแทนท์ จำกัด

Mockup แบบกดใช้งานได้จริงสำหรับ **ทดสอบ UAT ก่อนลงมือพัฒนา** ครอบคลุมรอบที่ 1 ตามลำดับใน `tasks.md`
ไม่มี backend · ข้อมูลทั้งหมดเป็นข้อมูลจำลอง · เก็บใน `localStorage` ของเบราว์เซอร์ผู้ทดสอบเท่านั้น

---

## เปิดใช้งาน

เป็นไฟล์ static ล้วน ไม่ต้อง build

```bash
# วิธีที่ง่ายที่สุด
npx http-server -p 8080 .
# แล้วเปิด http://localhost:8080
```

เปิดไฟล์ `index.html` ตรง ๆ ก็ได้ แต่แนะนำให้เสิร์ฟผ่าน http เพื่อให้ `localStorage` ทำงานถูกต้อง

deploy จริงเพียงคัดลอกทั้งโฟลเดอร์ไปวางใต้ web root — ไม่มี dependency ฝั่งเซิร์ฟเวอร์

### ไฟล์เดียวจบ สำหรับส่งให้ทีมทดสอบ

```bash
node tools/build-single-file.js          # ได้ไฟล์สองแบบใน dist/
node tools/build-single-file.js ~/ส่งทีม.html
```

เขียนออกสองไฟล์จากเนื้อเดียวกัน

| ไฟล์ | ใช้ทำอะไร |
|---|---|
| `dist/mockup-uat-standalone.html` | เอกสาร HTML สมบูรณ์ — ส่งให้ทีมทดสอบ แนบอีเมลหรือ LINE ดับเบิลคลิกเปิดได้เลย |
| `dist/mockup-single-file.html` | เนื้อล้วนไม่มี `<head>` สำหรับ publish เป็น artifact ซึ่งห่อ skeleton ให้เอง — ชื่อไฟล์ผูกกับ URL ที่แชร์ไปแล้ว ห้ามเปลี่ยน |

ปุ่มส่งออก CSV ทำงานได้ทั้งตอนเปิดผ่านเว็บเซิร์ฟเวอร์ ตอนเปิดจากไฟล์ในเครื่อง และตอนเปิดผ่านลิงก์ที่แชร์

## วิธีทดสอบ

1. เลือกผู้ใช้จากช่อง **"เข้าใช้งานในนาม"** มุมขวาบน — เมนูและสิทธิ์เปลี่ยนตามบทบาททันที
2. ไล่ทดสอบตาม `docs/uat-checklist.md` ซึ่งแปลงมาจาก "เกณฑ์ตรวจรับ" ในสเปกทีละข้อ
3. เจอปัญหาให้กดปุ่ม **"แจ้งผล UAT"** มุมขวาล่าง แล้วส่งออกเป็น CSV ตอนจบ
4. หน้า **"แผนที่ข้อกำหนด"** บอกว่ารหัสงานแต่ละข้อทดสอบได้ที่หน้าจอไหน และข้อไหนทดสอบที่นี่ไม่ได้
5. ปุ่ม **"รีเซ็ตข้อมูลตัวอย่าง"** บนแถบสีส้มคืนค่าทุกอย่าง (ผลการทดสอบที่บันทึกไว้ยังอยู่)

### ทดสอบอัตโนมัติ

```
node tests/run.js            ชุดตรรกะ — นับวัน ตัดถัง เส้นทางอนุมัติ สถานะรายวัน
node tests/run.js CI-18      เฉพาะข้อที่เกี่ยวกับรหัสนั้น
node tests/e2e/run-e2e.js    ชุดหน้าจอจริง เปิด Chromium กดใช้งานแทนคน
node tests/run-all.js        ทั้งสองชุดต่อกัน
```

ชุดตรรกะไม่ต้องติดตั้งอะไรเลย · ชุดหน้าจอต้องมี playwright + chromium ถ้าไม่มีจะข้ามให้เอง
รายการเทสต์ทั้งหมดและความครอบคลุมตามรหัสเกณฑ์ตรวจรับอยู่ที่ `docs/test-cases.md`
**การทดสอบอัตโนมัติไม่แทนที่ UAT** — เครื่องตอบได้แค่ว่ากติกายังทำงานถูก ส่วนคำถามว่าข้อกำหนดถูกต้องหรือไม่ ต้องให้คนกดเอง

### หลักการที่ยึดในโค้ด

- **ของกลางมีเจ้าของเดียว** — กติกาที่หลายเมนูใช้ร่วมกันอยู่ใน `core.js` ที่เดียว
  ไม่มีหน้าจอไหนคำนวณสถานะรายวัน ลำดับตัดถัง หรือหาผู้อนุมัติเอง
- **ห้าม hardcode ค่าตั้ง** — ทุกค่าอยู่ใน `SS.DEFAULT_PARAMS` และแก้ได้จากหน้าตั้งค่า
- **สถานะรายวันคำนวณตอนอ่าน** ไม่บันทึกทับตอนสิ้นวัน ตาม CI-14
- **หน้าเช็คอินไม่มีตัวเลขเงินหรือจำนวนมื้อ** ตาม CI-03

## ข้อจำกัดที่ต้องรู้

| เรื่อง | รายละเอียด |
|---|---|
| ไม่มี backend | เกณฑ์ตรวจรับที่สั่งให้ *"ตรวจใน payload หลังบ้าน"* (APV-05 · ALW-13) ทดสอบที่นี่ไม่ได้ |
| ไม่มีการแจ้งเตือน | CI-12 · LV-10 · APV-14 ต้องทดสอบบนระบบจริง |
| audit log ลบได้ | ข้อกำหนด APV-13 บังคับให้ลบไม่ได้แม้แต่แอดมิน ต้องทำที่สิทธิ์ฐานข้อมูล |
| ช่องวันที่แสดง ค.ศ. | `<input type="date"` ของเบราว์เซอร์แสดงตามภาษาของเครื่อง เปลี่ยนเป็น พ.ศ. ไม่ได้ · ข้อความอื่นทั้งหมดเป็น พ.ศ. ตาม S14 |
| ไม่มีงานเบื้องหลัง | สถานะ "ใช้แล้ว" และ "ตกไป" ที่ต้องเปลี่ยนตามเวลา ยังไม่มีตัวรันอัตโนมัติ |
| ทะเบียนพนักงานและไซต์เป็นของจำลอง | เจ้าของจริงคือเมนู Staff/Account และ โครงการ/ไซต์งาน ซึ่งยังไม่ถูกสร้าง |
