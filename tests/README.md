# tests/ — ชุดทดสอบต้นแบบ

ต้นแบบเป็น HTML + JavaScript ES5 ล้วน ไม่มี build ไม่มี dependency
ชุดทดสอบนี้จึงยึดกติกาเดียวกัน — **ไม่ลาก framework เข้ามา ไม่ต้อง `npm install`**

## รันยังไง

```
node tests/run.js            ชุดตรรกะทั้งหมด (ไม่ต้องติดตั้งอะไร)
node tests/run.js CI-18      เฉพาะข้อที่มีคำนี้ในรหัส ชื่อ หรือหมวด
node tests/e2e/run-e2e.js    ชุดหน้าจอจริงบน Chromium
node tests/run-all.js        ทั้งสองชุดต่อกัน
node tests/gen-doc.js        สร้าง docs/test-cases.md ใหม่จากโค้ดเทสต์
```

ออกด้วยรหัส 1 เมื่อมีข้อไม่ผ่าน — ต่อ CI ได้ทันทีถ้าวันหนึ่งมี

## โครงสร้าง

```
lib/harness.js     โหลด masters.js · seed.js · core.js · store.js เข้ามารันใน Node
                   ปลอม window / document / localStorage ให้ · ไม่แตะไฟล์ต้นแบบ
lib/tiny-test.js   ตัวรันเทสต์ — group() · test() · known() · expect
lib/fixtures.js    ตั้งฉาก — boot() · ตรึงวันที่/เวลา · เคลียร์เช็คอิน/ใบลา · หาวันทำงาน
unit/*.test.js     เทสต์ตามหมวด
e2e/run-e2e.js     เปิดเบราว์เซอร์จริง เสิร์ฟไฟล์ด้วย http ในตัว ไม่ต้องมี server แยก
```

## เขียนเทสต์เพิ่มยังไง

```js
var T = require('../lib/tiny-test.js');
var F = require('../lib/fixtures.js');
var test = T.test, x = T.expect;

test('CI-99', 'บอกเป็นภาษาไทยว่าคาดหวังอะไร', function () {
  var SS = F.boot();                    // ต้นแบบชุดใหม่ วันที่ตรึงไว้แล้ว
  x.eq(SS.core.leaveDays(lv), 3, 'เหตุผลที่ต้องเป็น 3');
});
```

กติกาสามข้อ

1. **รหัสแรกต้องเป็นรหัสเกณฑ์ตรวจรับจริง** (`CI-xx` · `LV-xx` · `BR-xx` · `APV-xx` · `ALW-xx` · `C1`…)
   ตัวรันสรุปความครอบคลุมจากรหัสนี้ และ `gen-doc.js` เอาไปทำตาราง
2. **ชื่อเทสต์เขียนเป็นภาษาไทยแบบที่คนของบริษัทอ่านรู้เรื่อง** ไม่ใช่ชื่อฟังก์ชัน
   เพราะรายการเทสต์คือส่วนหนึ่งของการส่งมอบ ไม่ใช่ของทีมพัฒนาอย่างเดียว
3. **เทสต์ต้องมาจากเกณฑ์ตรวจรับ ไม่ใช่จากโค้ดที่เขียนไว้แล้ว**
   ถ้าเขียนตามโค้ด จะได้แค่ยืนยันว่าโค้ดทำในสิ่งที่โค้ดทำ ซึ่งไม่มีประโยชน์

## ข้อค้นพบที่ยังไม่ควรแก้ — ใช้ `T.known()`

บางข้อ "ไม่ผ่าน" เพราะเป็นเรื่องที่ต้องให้คนตัดสิน ไม่ใช่บั๊กที่แก้เองได้
ใช้ `T.known(รหัส, ชื่อ, เหตุผลที่ยังไม่แก้, fn)` — ตัวรันจะคาดว่ามัน **ไม่ผ่าน**
ถ้าวันไหนมันผ่านขึ้นมา แปลว่ามีคนแก้แล้ว ตัวรันจะเตือนให้ย้ายกลับไปเป็น `test()` ปกติ
วิธีนี้ทำให้ข้อค้นพบไม่หายไปเงียบ ๆ และรายการก็ไม่แดงค้างจนคนเลิกสนใจ

## ข้อจำกัด

ชุดนี้ทดสอบ **ต้นแบบ** ไม่ใช่ระบบจริง — และไม่มีทางทดสอบระบบจริงได้ เพราะบริษัทไม่มีซอร์สโค้ดของระบบจริง
เรื่องที่ต้นแบบพิสูจน์ไม่ได้ (การบังคับสิทธิ์ PDPA · payload ของ API · การแจ้งเตือน LINE ·
audit log ที่ลบไม่ได้) รวมไว้ท้าย `docs/test-cases.md` และ `docs/test-report.md` แล้ว
**ห้ามติ๊กผ่านข้อเหล่านั้นจากผลการรันชุดนี้**
