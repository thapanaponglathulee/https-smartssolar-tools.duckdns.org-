# ชุดส่งงาน — โมดูลบุคคล Solar Tools Center

ปรับปรุง 8 ก.ย. 2569

**ส่งโฟลเดอร์ `dev-handoff` นี้ทั้งโฟลเดอร์ ไม่ต้องส่งอย่างอื่น** — ข้างในมีทุกอย่างที่ต้องใช้แล้ว

---

## งานนี้ทำอะไร

**บริษัทไม่มีซอร์สโค้ดของระบบจริง** และจะไม่ได้มา งานจึงเป็นสองขั้น

1. **ขั้นพิสูจน์ข้อกำหนด** — Claude Code สร้าง **ต้นแบบ** ขึ้นมาจากเอกสารในโฟลเดอร์นี้ ให้คนของบริษัทกดเล่นจริงจนมั่นใจว่าข้อกำหนดถูก
2. **ขั้นส่งมอบ** — ส่ง *ข้อกำหนดที่พิสูจน์แล้ว* + *ต้นแบบที่กดได้* ให้ผู้พัฒนาระบบจริงไปทำ

> ต้นแบบไม่ใช่ระบบจริง และไม่ต้องพยายามทำให้เป็นระบบจริง
> **หน้าที่ของต้นแบบคือทำให้ข้อกำหนดผิดถูกเห็นได้ด้วยตา**
> **ห้ามใส่ข้อมูลพนักงานจริง** ใช้ข้อมูลสมมติเท่านั้น · **ห้ามแตะระบบจริง** ไม่แก้โค้ด ไม่ยิง API

---

## เริ่มยังไง

1. เปิดเทอร์มินัลที่โฟลเดอร์ต้นแบบ แล้วสั่ง `claude`
2. **ย้าย `CLAUDE.md` ไปไว้ที่รากของโฟลเดอร์** — Claude Code อ่านไฟล์นี้เองทุกครั้งที่เริ่ม session
3. สั่งงานทีละรายการโดยอ้างรหัสงาน เช่น *"ทำ CI-04 ตาม `docs/spec-checkin.md`"*
4. ทุกงานมี **เกณฑ์ตรวจรับ** เขียนไว้ ใช้เป็นตัวตัดสินว่างานเสร็จหรือยัง

## ข้อกำหนดสองแบบ ต่างกันอย่างไร

| แบบ | ไฟล์ | บอกอะไร |
|---|---|---|
| **ข้อกำหนดงาน** | ส่วนใหญ่ | ต้องทำอะไร มีเกณฑ์ตรวจรับ อ้างรหัสงานได้ |
| **ข้อกำหนดหน้าจอ** | `spec-account.md` · `spec-org.md` · `spec-cert.md` | หน้าตาต้องเป็นอย่างไร มีสถานะอะไรบ้าง · จบด้วยหัวข้อ **"ข้อมูลที่หน้าจอเรียกร้อง"** · ทำขึ้นมากดเล่นก่อน แล้วใช้หน้าจอค้นว่าข้อมูลอะไรยังคิดไม่ถึง |

ทั้งสองแบบใช้ด้วยกัน ไม่ได้แทนที่กัน

## สิ่งที่ต้องมีในต้นแบบ นอกเหนือจากหน้าจอตามข้อกำหนด

1. **แถบสลับผู้ใช้** — "กำลังใช้งานเป็น: …" อยู่บนสุดตลอด กดเปลี่ยนเป็น พนักงาน · หัวหน้างาน · ฝ่ายบุคคล · แอดมิน · ผู้บริหาร ได้ทันทีโดยไม่ต้องล็อกอิน
   **ถ้าไม่มีตัวนี้ จะพิสูจน์เส้นทางอนุมัติไม่ได้เลยสักข้อ** เพราะข้อมูลเก็บแยกตามเบราว์เซอร์
   แถบนี้ **มีเฉพาะในต้นแบบ ห้ามเขียนลงข้อกำหนดที่ส่งให้ผู้พัฒนาระบบจริง**
2. **ปุ่มล้างข้อมูล และปุ่มโหลดข้อมูลตัวอย่าง** — เริ่มรอบทดสอบใหม่ได้ในคลิกเดียว
3. **หน้าจอ คำในปุ่ม และข้อความ error ต้องเป็นของจริงตามที่อยากได้** เพราะต้นแบบจะถูกส่งให้ผู้พัฒนาระบบจริงเป็นส่วนหนึ่งของการส่งมอบ ไม่ใช่ทิ้ง

## กติกาที่ห้ามฝ่าฝืน

1. **ห้าม hardcode ค่าที่เป็นนโยบายบริษัท** — เวลาเข้างาน จำนวนวันลา อัตราเบี้ยเลี้ยง วันหมดอายุ ทุกค่าต้องตั้งได้จากหน้าตั้งค่า
2. **ห้ามแสดงจำนวนเงินค่าอาหารหรือเบี้ยเลี้ยงรายไซต์ให้พนักงานทั่วไปเห็น**
3. **ระบบนี้ไม่เก็บเงินเดือน ค่าแรง เลขบัญชี หรือเลขบัตรประชาชน**
4. **ห้ามลบข้อมูลจริง** ใช้สถานะยกเลิกหรือพ้นสภาพแทน
5. **ทุกการแก้ไขย้อนหลังต้องมี audit log**
6. **เอกสารสุขภาพเป็นข้อมูลอ่อนไหวตาม PDPA** เปิดดูได้เฉพาะเจ้าตัว หัวหน้างานผู้อนุมัติ และฝ่ายบุคคล พร้อม log ทุกครั้งที่เปิด
7. **ห้ามสร้างบัญชีทดสอบหรือบัญชีที่ไม่ใช่คนจริงในทะเบียนพนักงาน**
8. **UI ภาษาไทยทั้งหมด** ใช้คำเดิมที่ระบบใช้อยู่ อย่าเปลี่ยนคำศัพท์
9. **ออกแบบสำหรับมือถือก่อน** ผู้ใช้หลักคือช่างหน้างาน สัญญาณไม่ดี

รายละเอียดทั้งหมดอยู่ใน `CLAUDE.md`
