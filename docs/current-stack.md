## 3. ฐานข้อมูล และไฟล์ที่กำหนดโครงสร้างตาราง

**ไม่มีฐานข้อมูล** — ค้นทั้ง repo ไม่พบไฟล์ `.sql`, migration, ORM, schema definition
หรือการเชื่อมต่อฐานข้อมูลใด ๆ และไม่พบ `fetch()`, `XMLHttpRequest`, `axios` หรือ `WebSocket`
แม้แต่ที่เดียว แปลว่าแอปนี้ไม่คุยกับเซิร์ฟเวอร์เลย

ที่เก็บข้อมูลจริงคือ **`localStorage` ของเบราว์เซอร์** คีย์เดียว:

```js
var KEY = 'ss-hr-uat-v2';          // assets/js/store.js:8
```

ทั้งระบบเก็บเป็น JSON ก้อนเดียวภายใต้คีย์นี้ (`assets/js/store.js:126`)

**ไฟล์ที่กำหนด "โครงสร้างตาราง" เท่าที่มี**

| ไฟล์ | กำหนดอะไร |
|---|---|
| `assets/js/store.js:83-108` | ฟังก์ชัน `fresh()` — รายชื่อคอลเลกชันทั้งหมดในระบบ เทียบได้กับ "รายชื่อตาราง" |
| `assets/js/masters.js` | ทะเบียนของกลางและค่าตั้งต้น — บทบาท ประเภทงาน ลักษณะการไปงาน โครงการ อัตราเบี้ยเลี้ยง ประเภทการลา สถานะ ประเภทวันในปฏิทิน พารามิเตอร์ระบบ |

## 8. โครงสร้างไฟล์หลัก

```

assets/css/app.css           ← สไตล์ทั้งหมด
assets/js/
  masters.js                 ← ค่าตั้งค่าและทะเบียนของกลาง
  seed.js                    ← ข้อมูลจำลอง
  core.js                    ← เครื่องคิดกติกาส่วนกลาง
  store.js                   ← state + การกระทำ + audit log + localStorage
  ui.js                      ← helper การแสดงผล (วันที่ พ.ศ. · modal · toast · CSV)
  views-emp.js               ← หน้าจอฝั่งพนักงาน
  views-team.js              ← หน้าจอฝั่งหัวหน้างาน
  views-admin.js             ← หน้าจอฝั่งฝ่ายบุคคล/แอดมิน + หน้าตั้งค่า
  app.js                     ← router · เมนูตามบทบาท · กล่องแจ้งผล UAT
docs/scope-uat.md            ← สรุปขอบเขตและข้อที่ยังไม่เคาะ

tools/build-single-file.js   ← รวมทุกอย่างเป็นไฟล์เดียว
dist/                        ← ผลลัพธ์จากสคริปต์ build (อยู่ใน .gitignore ไม่ถูก commit)
```

### หน้าเว็บอยู่ไฟล์ไหน

- **โครงหน้าเดียวของทั้งระบบ: `index.html`** — มี `<div id="view">` เป็นที่ว่าง แล้ว JS
  เขียนเนื้อหาลงไปทีละหน้า ไม่มีไฟล์ HTML อื่นเลยทั้ง repo
- **เนื้อหาของแต่ละหน้าจอ** อยู่ในไฟล์ `views-*.js` สามไฟล์ แต่ละหน้าคือฟังก์ชันหนึ่งตัวใน
  `SS.views` เช่น `SS.views.settings` ที่ `assets/js/views-admin.js:157`
- **ทะเบียนหน้าจอทั้ง 14 หน้า** อยู่ที่ตัวแปร `PAGES` ใน `assets/js/app.js:11-27`
  และตัวสลับหน้าอยู่ที่ฟังก์ชัน `go()` `assets/js/app.js:89`
- ลำดับการโหลดสคริปต์กำหนดไว้ที่ `index.html:75-83` — เรียงตามลำดับ dependency
  (`masters` → `seed` → `core` → `store` → `ui` → `views-*` → `app`) เปลี่ยนลำดับแล้วพัง

### API อยู่ไฟล์ไหน

**ไม่มี API** — ไม่มี backend ไม่มี endpoint ไม่มีการเรียกเครือข่ายใด ๆ ในโค้ด
(ค้น `fetch(`, `XMLHttpRequest`, `axios`, `/api/`, `WebSocket` แล้วไม่พบ)

สิ่งที่ทำหน้าที่แทน API คือ `SS.store` ใน `assets/js/store.js` — เป็นชั้นเดียวที่แก้ข้อมูลได้
ทุกการกระทำผ่านที่นี่หมด (`checkIn`, `submitLeave`, `decideLeave`, `cancelLeave`, `submitOT`,
`decideOT`, `decideComp`, `decideEditRequest`, `setParam`, `setEmployee`, ...) และทุกครั้งจะ
เขียน audit log แล้วบันทึกลง `localStorage`

> ข้อสังเกตสำหรับตอนพัฒนาจริง: `store.js` คือจุดที่จะเปลี่ยนเป็นการเรียก API จริง
> เพราะหน้าจอไม่ได้แตะข้อมูลตรง ๆ เลย

## 9. วิธี deploy และความต่างระหว่าง UAT กับระบบจริง

### วิธี deploy ที่มีเขียนไว้

`README.md` ระบุประโยคเดียว:

> *"deploy จริงเพียงคัดลอกทั้งโฟลเดอร์ไปวางใต้ web root — ไม่มี dependency ฝั่งเซิร์ฟเวอร์"*

แปลว่า: คัดลอก `index.html` + `assets/` ไปวางใต้ web root ของเว็บเซิร์ฟเวอร์ จบ
ไม่ต้อง build ไม่ต้องลง runtime ฝั่งเซิร์ฟเวอร์ ไม่ต้องตั้งค่าอะไร

ทางเลือกที่สอง: `node tools/build-single-file.js` แล้วส่งไฟล์
`dist/mockup-uat-standalone.html` ให้ผู้ทดสอบเปิดเอง (ไฟล์เดียวจบ ไม่ต้องมีเซิร์ฟเวอร์)

### ปลายทางที่เอกสารอ้างถึง

`smartssolar-tools.duckdns.org` — ปรากฏใน `README.md`, ใน footer ของ sidebar
(`index.html:35`) และเป็นชื่อ repo เอง แต่ **ไม่มีสคริปต์หรือ config ที่ deploy ไปที่นั่นจริง**
ใน repo (ไม่มี `.github/workflows/`, ไม่มี Dockerfile, ไม่มี `deploy.sh`, ไม่มี rsync/ftp config)

### ความต่างระหว่างขึ้น UAT กับขึ้นระบบจริง

**หาไม่เจอ** — repo นี้ไม่มีการแยกสภาพแวดล้อมเลย ไม่มีไฟล์ config ต่อ environment
ไม่มีตัวแปร environment ไม่มี build target ที่ต่างกัน ไม่มี branch strategy ที่เขียนไว้
สิ่งที่ deploy ได้มีชุดเดียวคือชุดที่เห็นใน repo

สิ่งที่พูดได้จากโค้ดจริงคือ **โค้ดชุดนี้ยังขึ้นระบบจริงไม่ได้** เพราะเป็น mockup ไม่ใช่ระบบ:
