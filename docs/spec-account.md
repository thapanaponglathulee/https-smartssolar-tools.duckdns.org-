## อ่านก่อน

**ไฟล์นี้เป็นข้อกำหนด _หน้าตา_ ไม่ใช่ข้อกำหนดพฤติกรรมทั้งหมด**
เป้าหมายคือให้สร้างหน้าจอขึ้นมากดเล่นก่อน แล้วใช้หน้าจอเป็นเครื่องมือตรวจว่า **ข้อมูลอะไรที่ยังคิดไม่ถึง**

- ทุกหน้าจอในไฟล์นี้ใช้ **ข้อมูลสมมติ** ห้ามใส่ชื่อพนักงานจริง
- ตัวเลขและชื่อในตัวอย่างเป็นของปลอมทั้งหมด ใส่ไว้ให้เห็นหน้าตาเท่านั้น
- ทำครบทุกสถานะของหน้าจอ ไม่ใช่แค่สถานะปกติ — ว่าง · กำลังโหลด · ไม่มีสิทธิ์ · ข้อมูลไม่ครบ
- **ข้อกำหนดพฤติกรรมของแต่ละงานอยู่ในใบสั่งงาน `ใบสั่งงานStaffAccount_SolarTools_2569-08-31.html` (ACC-01 ถึง ACC-19)** ไฟล์นี้ไม่แทนที่ใบนั้น

## สิ่งที่ต้องรู้ก่อนวาดหน้าจอ

| เรื่อง | ข้อสรุปที่เคาะแล้ว |
|---|---|
| **คน ≠ บัญชี** | หนึ่งคนคือหนึ่งคน · บัญชีคือวิธีเข้าระบบของคนนั้น · **ทุกบัญชีต้องผูกกับคนจริงหนึ่งคน** ห้ามมีบัญชีทดสอบหรือบัญชีกลางในทะเบียน (ACC-12 · ACC-18) |
| **ตำแหน่ง ≠ สิทธิ์** | ตำแหน่งคือหน้าที่ในองค์กร · สิทธิ์คือสิ่งที่กดได้ในระบบ · คนหนึ่ง**ถือหลายสิทธิ์ได้** ติ๊กได้หลายอัน (ACC-01) |
| **ไม่ลบคน** | ใช้สถานะแทน — ทดลองงาน · ประจำ · พ้นสภาพ · ระงับการใช้ (ACC-04) |
| **Staff ID ระบบออกให้** | ห้ามกรอกเอง ห้ามใช้ซ้ำแม้เจ้าของเดิมพ้นสภาพแล้ว (ACC-05) |
| **หัวหน้างานช่องเดียว** | ตัดช่องผู้อนุมัติการลาและผู้อนุมัติการยืมออก ให้ถามตารางอำนาจ S2 แทน (ACC-02 · ACC-03) |
| **Reporting Line ไม่ใช่สายอนุมัติ** | ใบลาไปหัวหน้างาน เบี้ยเลี้ยงไปฝ่ายบุคคล ผู้อนุมัติผูกกับ**เรื่อง** ไม่ผูกกับสายบังคับบัญชา |
| **ไม่มีเงินเดือน** | ไม่มีช่องเงินเดือน ค่าแรง เลขบัญชีธนาคาร หรือเลขบัตรประชาชนในหน้าจอใด ๆ |

**ห้าสิทธิ์ที่มีในระบบ** — พื้นฐาน · หัวหน้างาน · ฝ่ายบุคคล · ผู้บริหาร · แอดมิน

# หน้าจอที่ต้องสร้าง

## A1 · รายชื่อพนักงาน  `หน้าหลักของเมนูนี้`

```
┌────────────────────────────────────────────────────────────────┐
│  พนักงาน                                    [ + เพิ่มพนักงาน ] │
├────────────────────────────────────────────────────────────────┤
│  ทั้งหมด 31    ประจำ 26    ทดลองงาน 3    พ้นสภาพ 2            │
│                                          ⚠ ข้อมูลไม่ครบ 12 คน  │
├────────────────────────────────────────────────────────────────┤
│  [ ค้นหาชื่อหรือรหัส        ]  แผนก ▾  สถานะ ▾  สิทธิ์ ▾      │
├────────────────────────────────────────────────────────────────┤
│  รหัส     ชื่อ                ตำแหน่ง        แผนก      สถานะ  │
│  STF-011  สมชาย ใจดี          ช่างเทคนิค     ติดตั้ง   ประจำ  │
│  STF-012  วิภา ตั้งมั่น        ⚠ ยังไม่ระบุ   ติดตั้ง   ประจำ  │
│  STF-024  รัชนี ขันแข็ง        ฝ่ายบุคคล     สนับสนุน  ประจำ  │
│  STF-031  ธนา ศรีสุข          ช่างเทคนิค     O&M      ทดลอง  │
└────────────────────────────────────────────────────────────────┘
```

**สิ่งที่หน้านี้ต้องทำให้ถูก**

- การ์ดนับต้องตรงกับจำนวนแถวจริง — ของเดิมนับผิด แสดง 25 แต่มีจริง 23 (ACC-15)
- **ไม่มีปุ่มลบ** ทั้งในแถวและในหน้าโปรไฟล์ (ACC-04)
- แถวที่ข้อมูลไม่ครบต้องเห็นได้จากรายการเลย ไม่ต้องเปิดเข้าไปดู
- คนที่พ้นสภาพยังอยู่ในระบบ แต่ตั้งต้นไม่แสดง ต้องกรองเลือกถึงจะเห็น
- กดที่แถวเปิดโปรไฟล์ A2

**สถานะที่ต้องทำด้วย** — ยังไม่มีพนักงานสักคน · กำลังโหลด · ค้นหาแล้วไม่เจอ · ผู้ใช้ไม่มีสิทธิ์เห็นหน้านี้

## A2 · โปรไฟล์พนักงาน

แบ่งเป็นสี่แท็บ **อย่ายัดทุกอย่างลงหน้าเดียว**

```
  สมชาย ใจดี   STF-011                        [สถานะ: ประจำ ▾]
  ─────────────────────────────────────────────────────────────
   ข้อมูลส่วนตัว  |  งานและองค์กร  |  สิทธิ์  |  ประวัติการแก้ไข
```

### แท็บที่ 1 · ข้อมูลส่วนตัว

| ช่อง | บังคับ | ตัวอย่าง | ใครแก้ได้ |
|---|:-:|---|---|
| รหัสพนักงาน | — | STF-011 *(ระบบออกให้ แก้ไม่ได้)* | ไม่มีใคร |
| คำนำหน้า · ชื่อ · นามสกุล | ✔ | นาย · สมชาย · ใจดี | ฝ่ายบุคคล · แอดมิน |
| ชื่อเล่น | | ชาย | เจ้าตัวแก้ได้ |
| เบอร์โทร | ✔ | 08x-xxx-xxxx | เจ้าตัวแก้ได้ |
| อีเมล | | somchai@example.com | เจ้าตัวแก้ได้ |
| รูปโปรไฟล์ | | *(วงกลม ตั้งต้นเป็นตัวอักษรย่อ)* | เจ้าตัวแก้ได้ |
| วันเกิด | | 12 มี.ค. 2538 | ฝ่ายบุคคล |

> **ยังไม่เอาในรอบนี้** — ผู้ติดต่อกรณีฉุกเฉิน · เลขบัตรประชาชน · ที่อยู่
> ถ้าจะเพิ่มภายหลังต้องคุยเรื่อง PDPA ก่อน อย่าใส่ช่องไว้เฉย ๆ

### แท็บที่ 2 · งานและองค์กร

| ช่อง | บังคับ | ตัวอย่าง | หมายเหตุ |
|---|:-:|---|---|
| ตำแหน่งงาน | ✔ | ช่างเทคนิคติดตั้ง | **ดรอปดาวน์ ตั้งค่าได้** ห้ามพิมพ์อิสระ (ACC-06) · ของจริงตอนนี้ว่างทั้ง 31 คน |
| ฝ่าย / แผนก | ✔ | ปฏิบัติการ / ติดตั้ง | ดรอปดาวน์ ตั้งค่าได้ · ของจริงตอนนี้เป็นข้อความอิสระ สะกด 4 แบบ |
| หัวหน้างาน | ✔ | สมหมาย รักงาน (STF-005) | **ช่องเดียว** · เลือกจากคนที่ถือสิทธิ์หัวหน้างาน |
| สถานะพนักงาน | ✔ | ประจำ | ทดลองงาน · ประจำ · พ้นสภาพ · ระงับการใช้ |
| วันเริ่มงาน | ✔ | 1 ก.พ. 2568 | ใช้คิดโควตาลาตามสัดส่วน (ACC-08) |
| วันพ้นสภาพ | | — | บังคับกรอกเมื่อเลือกสถานะพ้นสภาพ |
| กะ | ✔ | กะปกติ | กะปกติ / กะกลางคืน (จาก CI-13) |
| ยกเว้นการเช็คอิน | | ไม่ยกเว้น | ติ๊กได้ ต้องผ่านผู้บริหาร (CI-07 · APV-11) |

**บล็อกโควตาวันลา** อยู่ในแท็บนี้ แสดงเป็นตารางอ่านอย่างเดียว มีปุ่ม "ขอแก้โควตา" ที่**เข้าคิวรอผู้บริหารอนุมัติ ไม่ใช่แก้ทันที** (ACC-09)

```
   ประเภท                 ปีนี้   ใช้ไป   คงเหลือ   หมดอายุ

   ลากิจธุระจำเป็น          6      1       5       31 ธ.ค. 2569

                                        [ ขอแก้โควตา ]
```

### แท็บที่ 3 · สิทธิ์

**ติ๊กได้หลายอัน** ไม่ใช่ดรอปดาวน์เลือกอย่างเดียว (ACC-01)

```
   ☑ พื้นฐาน        เช็คอิน ยื่นลา ดูข้อมูลตัวเอง
   ☑ หัวหน้างาน     อนุมัติใบลาของลูกทีม เห็นสถานะรายวันของลูกทีม
   ☐ ฝ่ายบุคคล      อนุมัติเบี้ยเลี้ยง ดูใบลาทุกคนแบบอ่านอย่างเดียว
   ☐ ผู้บริหาร      อนุมัติเรื่องที่ต้องขึ้นชั้น ดูรายงานรวม
   ☐ แอดมิน        ดูแลข้อมูลและการตั้งค่า **ไม่ใช่ผู้อนุมัติ**
```

- ใต้แต่ละสิทธิ์เขียนว่ากดอะไรได้บ้างเป็นภาษาคน ไม่ใช่ชื่อฟังก์ชัน
- เปลี่ยนสิทธิ์แล้วต้องขึ้นกล่องยืนยันที่บอกว่า **เปลี่ยนจากอะไรเป็นอะไร** และลง audit log (ACC-14)
- **มีสองอย่างที่ต้องเตือนเสมอ** — คนสุดท้ายที่ถือสิทธิ์ฝ่ายบุคคล และคนสุดท้ายที่ถือสิทธิ์ผู้บริหาร ห้ามปลดจนไม่เหลือใคร

**บล็อกบัญชีผู้ใช้** อยู่ท้ายแท็บนี้ — ชื่อผู้ใช้ · เข้าระบบล่าสุด · ปุ่ม "ตั้งรหัสผ่านใหม่"
การตั้งรหัสผ่านทับต้องขึ้นข้อความว่า **ระบบจะแจ้งเจ้าตัวและบันทึกไว้** ก่อนกดยืนยัน (ACC-11)

### แท็บที่ 4 · ประวัติการแก้ไข

ตารางอ่านอย่างเดียว — เมื่อไร · ใครแก้ · แก้ช่องไหน · จากค่าอะไรเป็นค่าอะไร
กรองตามช่วงวันที่ได้ · **ไม่มีปุ่มลบประวัติ**

## A3 · เพิ่มพนักงานใหม่

ทำเป็น **สามขั้น** ไม่ใช่ฟอร์มยาวหน้าเดียว

```
   ① ใครคือคนนี้   →   ② อยู่ตรงไหนในองค์กร   →   ③ เข้าระบบยังไง
```

- ขั้นที่ 1 ชื่อ นามสกุล เบอร์โทร วันเกิด
- ขั้นที่ 2 ตำแหน่ง แผนก หัวหน้างาน วันเริ่มงาน สถานะ กะ
- ขั้นที่ 3 สร้างบัญชีเลยหรือยังไม่สร้าง · ติ๊กสิทธิ์ · **Staff ID ระบบออกให้ตรงนี้ ให้เห็นก่อนกดบันทึก**
- ก่อนบันทึกแสดงสรุปทั้งสามขั้นให้ตรวจ
- หลังบันทึกเด้งไปหน้าโปรไฟล์ พร้อมแถบเขียวว่าเพิ่มสำเร็จและ Staff ID คืออะไร

> **ห้ามมีปุ่ม "สร้างบัญชีทดสอบ" หรือ "สร้างผู้ใช้ตัวอย่าง" ในหน้านี้** (ACC-12)

---

## A4 · หน้าโปรไฟล์ของตัวเอง  `พนักงานทั่วไปเห็นหน้านี้`

หน้าคนละหน้ากับ A2 — สั้นกว่ามาก (ACC-10)

- แก้ได้เอง: ชื่อเล่น · เบอร์โทร · อีเมล · รูปโปรไฟล์ · รหัสผ่านของตัวเอง
- อ่านอย่างเดียว: รหัส ตำแหน่ง แผนก หัวหน้างาน วันเริ่มงาน สถานะ
- เห็นโควตาวันลาของตัวเอง **แต่ไม่มีปุ่มขอแก้**
- **ไม่มีอะไรเกี่ยวกับสิทธิ์ในหน้านี้** พนักงานไม่ต้องเห็นว่าตัวเองถือสิทธิ์อะไร

## A5 · หน้าเตือนข้อมูลไม่ครบ  `ACC-13`

หน้ารวมงานค้างของฝ่ายบุคคล — ไม่ใช่ป๊อปอัปกวนตอนล็อกอิน

```
   ข้อมูลที่ต้องเติมให้ครบ
   ─────────────────────────────────────────────────
   ตำแหน่งงานยังว่าง                        31 คน  →
   แผนกยังเป็นข้อความอิสระ ต้องกาให้ตรง      31 คน  →
   ยังไม่มีใครถือสิทธิ์ผู้บริหาร              ทั้งระบบ →
   ฝ่ายบุคคลมีคนเดียว ยังไม่มีผู้สำรอง        ทั้งระบบ →
   วันเริ่มงานยังว่าง                         8 คน  →
```

กดแต่ละบรรทัดแล้วไปที่รายการที่กรองไว้แล้ว **ไม่ใช่ไปหน้ารวมแล้วให้ค้นเอง**
ตัวเลขทั้งหมดในตัวอย่างนี้เป็นของสมมติ แต่สี่บรรทัดแรกเป็นปัญหาจริงที่ต้องมีที่ให้เห็น

---

## A6 · ดูในมุมมองของบทบาทอื่น  `ACC-19` `อ่านอย่างเดียว`

- เลือกบทบาทแล้วหน้าจอเปลี่ยนเป็นสิ่งที่บทบาทนั้นเห็น
- **มีแถบสีค้างบนสุดตลอดเวลา** ว่ากำลังดูในมุมมองใคร กดออกได้ตลอด
- กดอะไรที่เปลี่ยนข้อมูลไม่ได้เลยสักปุ่ม · เข้าโหมดนี้ลง audit log
- **ไม่ใช่ตัวสลับผู้ใช้ของต้นแบบ** ตัวสลับผู้ใช้เป็นของต้นแบบเท่านั้น อันนี้เป็นของระบบจริง

---

## A7 · ขั้นตอนเมื่อคนพ้นสภาพ  `ACC-16`

ไม่ใช่แค่เปลี่ยนดรอปดาวน์ — ต้องเป็นขั้นตอนที่มีรายการตรวจ

```
   ให้ สมชาย ใจดี พ้นสภาพ
   ─────────────────────────────────────────────
   วันพ้นสภาพ            [ 30 ก.ย. 2569 ]
   
   ⚠ คนนี้เป็นหัวหน้างานของอีก 6 คน
      ต้องเลือกหัวหน้างานคนใหม่ให้ก่อน  [ เลือก ▾ ]
   ⚠ มีใบลารออนุมัติที่รอเขาอยู่ 2 ใบ
      จะโอนไปให้ใคร                      [ เลือก ▾ ]
   ⚠ ยอดลาพักผ่อนคงเหลือ 5 วัน
      บันทึกไว้ให้ฝ่ายบุคคลจัดการนอกระบบ
   
                                [ ยกเลิก ]  [ ยืนยัน ]
```

**ห้ามให้กดยืนยันผ่านถ้ายังไม่เคลียร์สองข้อแรก** — ไม่งั้นใบลาค้างอยู่กับคนที่ไม่อยู่แล้ว

**ช่องว่างที่จะเห็นทันทีเมื่อสร้างหน้าจอ**

1. ตำแหน่งและแผนกเป็นดรอปดาวน์ที่ตั้งค่าได้ — **แต่ยังไม่มีหน้าตั้งค่าของมัน** ดู `spec-org.md`
2. โควตาวันลามาจากไหนตอนพนักงานเข้าใหม่กลางปี — คิดตามสัดส่วนอย่างไร ใครเป็นคนกดคำนวณ
3. ตอนเปลี่ยนหัวหน้างานของคนหนึ่ง ใบลาที่ค้างอยู่กับหัวหน้าคนเก่าจะไปไหน
4. คนที่ถือสองสิทธิ์พร้อมกัน เช่นหัวหน้างาน + ฝ่ายบุคคล จะอนุมัติของตัวเองได้ไหม — **กติกาบอกว่าห้าม** หน้าจอต้องแสดงให้เห็นว่ากันไว้อย่างไร

## เรื่องที่ยังไม่เคาะ ต้องตอบก่อนหน้าจอจะสมบูรณ์

1. **ใครเป็นผู้บริหารในระบบ** — ยังไม่มีใครถือสิทธิ์นี้เลย ทั้ง APV และ ACC ยืนอยู่บนมัน
2. **ใครเป็นผู้สำรองของฝ่ายบุคคล** — ตอนนี้มีคนเดียว วันที่เขาลา รอบจ่ายค้างทั้งบริษัท
3. **หัวหน้างานควรมีกี่คน** — วันนี้มี 2 คนสำหรับ 31 คน ตรงกับความจริงหน้างานหรือไม่
4. **ผู้อนุมัติสำรองเป็นรายคนหรือรายบทบาท** — เอกสาร Staff/Account บอกรายบทบาท แต่ LV-05 เขียนรายคน **ขัดกันอยู่**
5. **13 คนที่กรอกว่า Project Manager** เป็นตำแหน่งจริงหรือไม่
6. **เลข Staff ID ที่หายไป** (002–010, 036, 038, 039) เคยมีคนใช้จริงหรือข้ามไป
