รายการนี้ **ไม่แทนที่** `docs/uat-checklist.md` ซึ่งเป็นรายการที่คนกดทดสอบเอง
สองรายการทำคนละหน้าที่

| | รายการทดสอบอัตโนมัติ (ไฟล์นี้) | รายการ UAT (`uat-checklist.md`) |
|---|---|---|
| ใครรัน | เครื่อง รันซ้ำได้ทุกครั้งที่แก้โค้ด | คนของบริษัท กดเองบนหน้าจอจริง |
| ตรวจอะไร | กติกาและตัวเลข — นับวัน ตัดถัง เส้นทางอนุมัติ สถานะรายวัน | หน้าตา ความเข้าใจ ความรู้สึกตอนใช้ คำในปุ่ม |
| ตอบคำถาม | "กติกาที่เขียนไว้ ยังทำงานถูกอยู่ไหม" | "ข้อกำหนดที่เขียนไว้ ถูกต้องตามที่บริษัทต้องการไหม" |

## วิธีรัน

```
node tests/run.js            # ชุดตรรกะทั้งหมด
node tests/run.js CI-18      # เฉพาะข้อที่เกี่ยวกับ CI-18
node tests/e2e/run-e2e.js    # ชุดหน้าจอจริงบน Chromium
node tests/run-all.js        # ทั้งสองชุดต่อกัน
```

ไม่ต้องติดตั้งอะไรสำหรับชุดตรรกะ · ชุดหน้าจอต้องมี playwright + chromium ในเครื่อง
ถ้าไม่มี ชุดหน้าจอจะข้ามให้เองพร้อมบอกวิธีติดตั้ง ไม่ทำให้ทั้งชุดล้ม

เทสต์เหล่านี้ตั้งใจให้ "ไม่ผ่าน" เพราะเป็นเรื่องที่ต้องให้คนตัดสิน ไม่ใช่บั๊กที่แก้เองได้
ถ้าวันไหนมันผ่านขึ้นมา ตัวรันจะเตือนให้ย้ายกลับไปเป็นเทสต์ปกติ

- **`APV-03` เรื่องที่ขึ้นผู้บริหาร เมื่อผู้ยื่นคือผู้บริหารเอง ระบบยังส่งกลับไปหาตัวเอง**
  ในทะเบียนมีผู้บริหารคนเดียว จึงยังไม่มีคำตอบว่า "ใครอนุมัติเรื่องของผู้บริหาร" — เป็นข้อที่ต้องให้บริษัทตัดสิน (ตั้งผู้บริหารคนที่สอง · ให้ฝ่ายบุคคลรับ · หรือรับทราบว่าอนุมัติเองได้) ยังไม่ควรให้ Claude Code เลือกแทน · เห็นชัดที่เรื่อง allowance-adj / checkin-exempt / leave-quota / role-change / calendar-year
- **`C4` ต้นแบบยังไม่บังคับสิทธิ์การเปิดดูเอกสารอ่อนไหว — ใครสลับบทบาทเป็นใครก็เรียกดูได้**
  ตรงตามที่ CLAUDE.md ระบุไว้ว่า "audit log และสิทธิ์ PDPA ในต้นแบบเป็นแค่การแสดงให้เห็น ไม่ใช่การบังคับ" การบังคับจริงต้องทำที่ backend ของระบบจริง — ห้ามติ๊กผ่านข้อนี้จากการทดสอบในต้นแบบ

## สิ่งที่เทสต์ชุดนี้พิสูจน์ไม่ได้

ยกไปทดสอบบนระบบจริงเท่านั้น — ห้ามติ๊กผ่านจากผลของต้นแบบ

- การบังคับสิทธิ์ PDPA ที่หลังบ้าน (ต้นแบบทำได้แค่แสดงให้เห็น)
- payload ที่ส่งจาก API ต้องไม่มีข้อมูลเบี้ยเลี้ยงเมื่อผู้ใช้เป็นหัวหน้างาน (APV-05 · ALW-13)
- การแจ้งเตือน 09:00 · LINE · ปุ่มอนุมัติในข้อความ (CI-12 · LV-10 · APV-14)
- บันทึกการอนุมัติที่ลบไม่ได้แม้แต่แอดมิน (APV-13)
- การแปลงข้อมูลเช็คอินเดิม จำนวนก่อน-หลังต้องเท่ากันเป๊ะ (CI-21)
- การเรียก `getProjects` ใหม่ทุกครั้งที่กลับเข้าหน้าเช็คอิน (CI-01)
