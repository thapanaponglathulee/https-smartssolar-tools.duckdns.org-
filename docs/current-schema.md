### เบี้ยเลี้ยง — ไม่มีตารางเก็บยอด

ค้นแล้ว **ไม่พบคอลเลกชันที่เก็บรายการเบี้ยเลี้ยงหรือยอดเงิน** สิ่งที่เก็บจริงมีแค่ `rates`
คืออัตราต่อมื้อของแต่ละไซต์ตามช่วงวัน

ยอดเบี้ยเลี้ยงคำนวณสดจากใบเช็คอินทุกครั้งที่แสดงผล ด้วย `SS.core.allowanceOf(ci)`
(`assets/js/core.js:376`) สูตรคือ:

```
จำนวนมื้อ (จาก travelTypes ของใบเช็คอิน + 1 ถ้า overtime)  ×  อัตราของไซต์ ณ วันนั้น (จาก rates)
```

โดยข้ามให้ไม่เกิดรายการถ้าวันนั้นมีใบลาที่อนุมัติแล้ว (ALW-10)

> ตรงกับที่ `docs/scope-uat.md` ระบุว่าโมดูลเบี้ยเลี้ยงทั้งหมด (ALW) อยู่ใน **รอบที่ 2**
> ยังไม่ได้ทำในรอบนี้

### สิทธิ์ผู้ใช้ — กระจายอยู่ 3 ที่ ไม่มีตารางสิทธิ์รวม

| ที่อยู่ | คุมอะไร |
|---|---|
| `employees.role` | บทบาทของแต่ละคน 1 ใน 5 (`employee` · `manager` · `hr` · `exec` · `admin`) นิยามที่ `SS.ROLES` (`masters.js:30`) |
| `NAV` ใน `assets/js/app.js:28-39` | เมนูที่แต่ละบทบาทเห็น — และเป็นตัวบังคับสิทธิ์เข้าหน้าจอด้วย ฟังก์ชัน `go()` (`app.js:89`) เด้งกลับถ้าเปิดหน้าที่บทบาทนั้นไม่มีสิทธิ์ |
| `authority` | ใครอนุมัติเรื่องไหน — อ่านผ่าน `SS.core.approverOf()` (`core.js:239`) พร้อมกฎ fallback ตาม APV-02 / APV-03 / J4 |

**ไม่มีระบบยืนยันตัวตน** — ไม่มีรหัสผ่าน ไม่มี token ไม่มี session ผู้ใช้เปลี่ยนตัวเองเป็นใคร
ก็ได้จากช่อง "เข้าใช้งานในนาม" (`index.html:45-48`) ซึ่งเป็นพฤติกรรมที่ตั้งใจของ mockup UAT

## สิ่งที่ยังไม่มีในโครงสร้างนี้ (สำหรับตอนออกแบบฐานข้อมูลจริง)

รายการนี้มาจากสิ่งที่ **ค้นแล้วไม่พบ** ในโค้ด ไม่ใช่ข้อเสนอแนะ

- ไม่มีตารางผู้ใช้/รหัสผ่าน/สิทธิ์เข้าระบบแยกจากตารางพนักงาน
- ไม่มีตารางไฟล์แนบ — `leaves.attachment` เก็บแค่ชื่อไฟล์เป็น string
- ไม่มีตารางเบี้ยเลี้ยงและรอบตัดจ่าย (มีแค่พารามิเตอร์ `payCycleStartDay`)
- ไม่มีตารางการแจ้งเตือน
- ไม่มีคอลัมน์ `createdAt` / `updatedAt` ที่เป็นมาตรฐานเดียวกันทุกตาราง — บางตารางมี บางตารางไม่มี
  และรูปแบบไม่เหมือนกัน (`checkins.createdAt` เป็น `YYYY-MM-DD HH:MM` แต่ `audit.at` เป็น ISO timestamp)
- ไม่มี soft delete ที่เป็นมาตรฐานเดียวกัน — `checkins` ใช้ `status: 'cancelled'`
  ส่วน `employees` ใช้ `active: false` และบางตารางลบทิ้งจริง (`feedback`)
