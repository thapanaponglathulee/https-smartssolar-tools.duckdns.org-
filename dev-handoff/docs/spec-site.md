# ข้อกำหนด — โครงการ/ไซต์งาน

จัดทำ 8 ก.ย. 2569 · สถานะ: **ไม่อยู่ในเฟสนี้ — เก็บไว้เป็นบันทึกเท่านั้น**

> **ห้ามสั่งงานจากไฟล์นี้ ห้ามสร้างหน้าจอจากไฟล์นี้ และห้ามใส่ลงต้นแบบ**
> ไฟล์นี้มีไว้เพื่อไม่ให้ความต้องการสามข้อนี้หายไปเงียบ ๆ และเพื่อให้รู้ว่าเมนูอื่นพึ่งอะไรอยู่บ้าง

## สิ่งที่ต้องระวังเพราะสามข้อนี้ไม่ทำ

### 1 · เก็บข้อมูลให้ถูกตั้งแต่วันนี้ แม้ยังไม่มีรายงาน  `สำคัญที่สุด`

SITE-02 ไม่ทำในเฟสนี้ แต่ **ข้อมูลกำลังถูกบันทึกอยู่ทุกวันตั้งแต่วันนี้** ถ้าบันทึกผิดวิธี ระบบ project management ที่มาทีหลังจะได้ข้อมูลที่ใช้ไม่ได้ และย้อนกลับไปแก้ไม่ได้แล้ว

สิ่งที่ต้องบันทึกให้ถูกในทุกเช็คอิน แม้จะยังไม่มีใครเอาไปใช้

- **ไซต์หลักของวัน** และ **รายการไซต์ที่แวะ** แยกกันชัดเจน (CI-25)
- **กติกาการนับคน-วัน** — หนึ่งคนหนึ่งวัน = 1.0 ยกให้ไซต์หลัก · ไซต์ที่แวะนับเป็นจำนวนครั้ง **ห้ามนับ 1 คน-วันให้ทุกไซต์ที่แวะ** · กติกานี้อยู่ในโครงสร้างข้อมูล ไม่ใช่อยู่ในรายงาน จึงต้องถูกตั้งแต่วันนี้
- **ประเภทงาน** ของทั้งไซต์หลักและไซต์ที่แวะ (S19)
- **เหตุผลไซต์หยุดงาน** เมื่อไปถึงแล้วทำงานไม่ได้ (S21 · CI-26) — เพื่อให้ภายหลังแยกได้ว่าวันไหนเสียไปกับฝน วันไหนเสียไปกับการรอของ

> ถ้าไม่ทำข้อนี้ ตอนทำ project management จะเจอเหมือนที่เจอกับเช็คอินเก่า 3,300 รายการที่ระบุโครงการไม่ได้ — ข้อมูลมีอยู่ แต่เอาไปใช้ไม่ได้

### 2 · พิกัดไซต์ยังต้องมี แต่ไม่ใช่งานของเมนูนี้

CI-28 ต้องใช้พิกัดที่ตั้งของไซต์เพื่อคำนวณระยะห่าง — **เป็นการเพิ่มฟิลด์หนึ่งช่องในหน้าจัดการโครงการที่มีอยู่แล้วใน Admin Panel** ไม่ใช่การสร้างเมนูใหม่ จึงยังทำได้ในเฟสนี้

ระหว่างที่ยังไม่มีพิกัดไซต์ ให้ CI-28 เก็บพิกัดดิบของการเช็คอินไว้ก่อน แล้วค่อยคำนวณระยะย้อนหลังเมื่อไซต์มีพิกัดครบ

### 3 · สิ่งที่เมนูอื่นต้องยอมรับว่าทำไม่ได้ในเฟสนี้

| เมนู | สิ่งที่ทำไม่ได้ | ทางออกในเฟสนี้ |
|---|---|---|
| เช็คอิน CI-26 | หัวหน้าประกาศปิดไซต์ทีเดียวแล้วทุกคนที่ถูกมอบหมายได้อัตโนมัติ | หัวหน้ากดแทนลูกทีมทีละชุด **เฉพาะคนที่เช็คอินไซต์นั้นแล้ว** และลง audit log |
| ลา LV-09 | ตั้งเพดานคนลาพร้อมกัน **รายไซต์** และผูกกับวัน COD ของโครงการ | คงเพดาน **รายทีม** ไว้ และตั้งช่วงห้ามลาด้วยมือทุกครั้งที่มีงานส่งมอบ — ต้องมีคนรับผิดชอบว่าใครเป็นคนกา ไม่งั้นจะลืม |
| ปฏิทิน | ปฏิทินไซต์งาน ใครไปไซต์ไหนวันไหนล่วงหน้า | เห็นได้เฉพาะย้อนหลังจากเช็คอิน ไม่เห็นล่วงหน้า |
| ทุกเมนู | ตัวเลขกำลังคนที่ไซต์ที่รวมผู้รับเหมาช่วง | ตัวเลขทุกตัวในระบบนี้หมายถึง **พนักงานบริษัทเท่านั้น** ต้องเขียนกำกับไว้บนหน้าจอและในรายงาน ไม่ให้เข้าใจผิดว่าเป็นกำลังคนทั้งหมดที่ไซต์ |

> **Reporting Line ไม่เท่ากับสายอนุมัติ** — ยืนยัน 8 ก.ย. 2569 ว่าใบลาไปหัวหน้างาน เบี้ยเลี้ยงไปฝ่ายบุคคล เหมือนเดิม
> Organization Chart เป็นข้อมูลโครงสร้างองค์กร **ไม่ได้เป็นตัวกำหนดว่าใครอนุมัติอะไร** ผู้อนุมัติผูกกับเรื่อง ไม่ผูกกับสายบังคับบัญชา

**เส้นแบ่งกับ project management**

| ใครถือ | อะไร |
|---|---|
| **โมดูลบุคคล** | ข้อเท็จจริงรายคนรายวัน — คนนี้ วันนี้ อยู่ไซต์ไหน ทำงานประเภทไหน สถานะอะไร ได้กี่มื้อ · เก็บให้ถูก ให้ครบ ให้ตรวจสอบย้อนกลับได้ |
| **project management** | การรวมยอดในมุมของโครงการ — คน-วันต่อไซต์ ต้นทุนแรงงาน ความคืบหน้า แผนกำลังคน |
| **จุดส่งต่อ** | โมดูลบุคคลส่งออก *แถวรายวันรายคน* ที่มี ไซต์หลัก · ไซต์ที่แวะ · ประเภทงาน · สถานะรายวัน · เหตุผลไซต์หยุดงาน — **ไม่รวมยอด ไม่ตีความ ไม่มีตัวเงิน** |

**คน-วันเป็นของ project management** — โมดูลบุคคลไม่ออกรายงานคน-วัน แต่**ต้องเก็บข้อมูลให้รวมยอดได้ถูกต้อง** ตามกติกาใน CI-25

## ข้อมูลเช็คอินเก่าที่ระบุโครงการไม่ได้ — เคาะแล้ว 8 ก.ย. 2569

**มติ: ปล่อย ไม่จับคู่ย้อนหลัง** — เช็คอินกว่า 3,300 ครั้งที่ระบุโครงการไม่ได้ (WS4 976 · WS 814 · TPC2 634 · Office A 359 · LYHS 347 · Sappe 213 …) จะไม่มีการไล่จับคู่กับโครงการจริง

**สิ่งที่ต้องทำเพราะปล่อย**

- ข้อมูลเก่าเก็บรหัสดิบไว้ตามเดิม ไปอยู่ในถัง **"ไม่ระบุโครงการ"** · **ห้ามเดาแทนผู้ใช้ ห้ามจับคู่อัตโนมัติ** (ตรงกับ CI-21 ที่เขียนไว้แล้ว)
- ทุกหน้าจอและทุกรายงานที่แยกตามไซต์ ต้องมี **วันเริ่มต้นที่ข้อมูลเชื่อถือได้** กำกับ คือวันที่โครงสร้างประเภทงานใหม่ (CI-15/CI-16) เริ่มใช้จริง — ก่อนหน้านั้นไม่ต้องแสดง หรือแสดงพร้อมคำเตือน
- ประวัติเช็คอินของพนักงาน (CI-22 CI-23) ต้องแสดงรายการเก่าได้โดยไม่พัง ขึ้นว่า "ไม่ระบุโครงการ" ไม่ใช่ช่องว่างหรือ error
- **ตัวเลขคน-วันย้อนหลังก่อนวันเริ่มต้นนั้นใช้ไม่ได้** ต้องบอก project management ให้ชัดตั้งแต่ต้น จะได้ไม่เอาไปใช้ตั้งราคา
