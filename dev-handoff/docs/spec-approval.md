# สเปกแท็บอนุมัติ

ระบบ smartssolar-tools.duckdns.org · โมดูลบุคคล · 31 ส.ค. 2569
รหัสงาน APV-01 ถึง APV-14

---

## หลักการ

**ผู้อนุมัติผูกกับ "เรื่อง" ไม่ใช่สายบังคับบัญชา**

- **ใบลาและทุกอย่างที่เกี่ยวกับเวลาทำงาน → หัวหน้างาน**
- **เบี้ยเลี้ยง → ฝ่ายบุคคล**

สองสายนี้ไม่ข้ามกัน **ในเรื่องอำนาจตัดสิน** — หัวหน้างานไม่มีเบี้ยเลี้ยงในคิว ฝ่ายบุคคลไม่มีใบลาในคิว

> **แก้ 1 ก.ย. 2569 — แยก "คิวอนุมัติ" ออกจาก "สิทธิ์ดูข้อมูล"**
> เดิมเขียนสั้นว่า "ฝ่ายบุคคลไม่เห็นใบลา" ซึ่งกว้างเกินไป ถ้าทำตามตัวอักษรฝ่ายบุคคลจะทำงานประจำไม่ได้
> **ฝ่ายบุคคลเห็นใบลาที่รออนุมัติได้แบบอ่านอย่างเดียว** และเห็นโควตา ยอดคงเหลือ กับประวัติการลาที่อนุมัติแล้วของทุกคน
> **แต่ไม่มีปุ่มอนุมัติ ปฏิเสธ หรือเร่งรัดถึงพนักงานโดยตรง** ยกเว้นใบที่ตกมาแบบ fallback (J4) และคิว "รอตรวจสอบ" (CI-14)
> สิทธิ์นี้ผูกกับบทบาท ไม่ผูกกับตัวคน

ชั้นอำนาจมี **2 ชั้น** — หัวหน้างาน · ผู้บริหาร (บริษัทมีราว 31 คน ไม่ต้องมีสามชั้น)

**ไม่ขึ้นชั้นตามจำนวนวันลา** ลากี่วันก็จบที่หัวหน้างาน
**ไม่ส่งต่ออัตโนมัติเมื่อค้าง** คงค้างไว้กับคนเดิม แล้วเตือนซ้ำ

## ตารางอำนาจอนุมัติ

ต้องเป็นค่าตั้งค่าที่แก้ได้ **ห้าม hardcode**

| เรื่อง | ผู้อนุมัติ | ผู้สำรอง | ข้อยกเว้น |
|---|---|---|---|
| ใบลา ทุกประเภท ทุกจำนวนวัน | หัวหน้างานของผู้ยื่น | ผู้อนุมัติสำรอง ไม่มี → **ฝ่ายบุคคล** (J4) | ประเภทที่กฎหมายห้ามปฏิเสธ = รับทราบเท่านั้น · ใบของฝ่ายบุคคลเอง → ผู้บริหาร |
| ยกเลิกใบลาที่อนุมัติแล้ว | หัวหน้างาน | เหมือนใบลา | คืนโควตาอัตโนมัติเมื่ออนุมัติ |
| แก้เช็คอินข้ามวัน | หัวหน้างาน | เหมือนใบลา | แก้ในวันเดียวกันไม่ต้องอนุมัติ |
| วันชดเชย (วันหยุด/นอกเวลา) | หัวหน้างาน | เหมือนใบลา | สร้างสิทธิ์วันลาใหม่ |
| **เบี้ยเลี้ยงรายรอบ** | **ฝ่ายบุคคล** | ฝ่ายบุคคลสำรอง | รายการของฝ่ายบุคคลเอง → ผู้บริหาร |
| **ปิดรอบจ่าย** | **ฝ่ายบุคคล** | ฝ่ายบุคคลสำรอง | ต้องเคลียร์รายการค้างก่อน |
| ปรับยอดเบี้ยเลี้ยงด้วยมือ | ผู้บริหาร | — | ต้องมีเหตุผล เก็บทั้งสองยอด |
| ยกเว้นการเช็คอินรายบุคคล | ผู้บริหาร | — | มีผลถาวร |
| แก้สิทธิ์วันลารายคน | ผู้บริหาร | — | |
| แก้อัตราเบี้ยเลี้ยงรายไซต์ | ผู้บริหาร | — | กระทบทุกคนในไซต์ ทุกวัน |
| ประกาศปฏิทินทำงานทั้งปี | ผู้บริหาร | — | อนุมัติครั้งเดียวตอนประกาศ |
| เปลี่ยนบทบาทผู้ใช้ | ผู้บริหาร | — | โดยเฉพาะการตั้งแอดมิน |

**จงใจไม่ต้องอนุมัติ** — เปลี่ยนลักษณะการไปงานจากค่าตั้งต้น (CI-18) ใช้ธงแทน · แปลงสถานที่อื่นเป็นโครงการ (CI-17) เป็นงานธุรการ · เช็คอินประจำวัน

> ถ้าใส่การอนุมัติกับทุกอย่าง คนอนุมัติจะกดผ่านรวดโดยไม่อ่าน แล้วการอนุมัติทั้งระบบจะไร้ความหมาย

## Workflow มาตรฐาน 5 ขั้น

```
1 ยื่น           → บันทึกเวลาและตัวตน
2 ตรวจอัตโนมัติ   → ผ่าน: เข้าคิว | ไม่ผ่าน: ตีกลับทันที (ไม่ใช่ "ปฏิเสธ")
3 รออนุมัติ       → เข้าคิวผู้อนุมัติตามตารางอำนาจ
4 ตัดสิน          → อนุมัติ / ไม่อนุมัติ / ขอข้อมูลเพิ่ม
5 แจ้งผล          → ทุกกรณี รวมกรณีไม่อนุมัติ
```

**กฎเหล็ก 4 ข้อ**

1. ห้ามอนุมัติของตัวเอง → ขึ้นไปอีกหนึ่งชั้นอัตโนมัติ
2. ผู้สำรองทำงานเมื่อผู้อนุมัติหลักลา ไม่อยู่ หรือเป็นผู้ยื่นเอง
3. ค้างแล้วเตือนซ้ำ **ไม่ส่งต่ออัตโนมัติ**
4. ปฏิเสธต้องมีเหตุผลเสมอ และแจ้งผู้ยื่นทันที

## รายการงาน

### รอบ 1 — ฐาน

**APV-01 ตารางอำนาจอนุมัติเป็นค่าตั้งค่า**
ทุกที่ที่ถามว่า "ใครอนุมัติเรื่องนี้" ต้องถามตารางนี้ที่เดียว ห้ามเขียนเงื่อนไขซ้ำในหน้าอื่น · เพิ่มชนิดเรื่องใหม่ได้โดยไม่แก้โค้ด · บันทึกว่าใครแก้ตารางเมื่อไหร่ (การแก้ตารางนี้ = การเปลี่ยนอำนาจ)
*ตรวจรับ* เปลี่ยนผู้อนุมัติเบี้ยเลี้ยงในหน้าตั้งค่า → รายการใหม่วิ่งไปหาคนใหม่ทันที ไม่ต้องแก้โค้ด

**APV-02 ผู้อนุมัติผูกกับบทบาท และมีผู้สำรอง**
อ้างบทบาท ("หัวหน้างานของผู้ยื่น", "ฝ่ายบุคคล") ไม่ใช่ชื่อคน · ฝ่ายบุคคลต้องมีสำรองเสมอ ไม่งั้นคนเดียวลาหยุด รอบจ่ายค้างทั้งบริษัท · ไม่มีทั้งหลักและสำรอง → **ฝ่ายบุคคล** (J4) + เตือนแอดมินให้ไปตั้งค่าผู้สำรอง · ฝ่ายบุคคลเห็นเฉพาะใบที่ตกมาแบบ fallback ไม่ใช่ทุกใบ · ใบที่เป็นของฝ่ายบุคคลเอง → ผู้บริหาร · ผู้สำรองกด = บันทึกว่าอนุมัติแทน พร้อมเหตุผล
*ตรวจรับ* ตั้งผู้อนุมัติหลักให้ลา → เรื่องวิ่งไปหาผู้สำรองเอง และบันทึกแสดงว่าเป็นการอนุมัติแทน

**APV-03 ห้ามอนุมัติของตัวเอง**
หัวหน้างานยื่นใบลาเอง → ผู้บริหาร · ฝ่ายบุคคลยื่นเบี้ยเลี้ยงเอง → ผู้บริหาร · **กติกานี้มีผลเหนือทุกกติกาอื่น รวมถึงทางแอดมิน**
*ตรวจรับ* ล็อกอินเป็นฝ่ายบุคคล ยื่นเบี้ยเลี้ยงตัวเอง → ไม่อยู่ในคิวตัวเอง แต่อยู่ในคิวผู้บริหาร

**APV-04 ขั้นตรวจอัตโนมัติก่อนถึงคน**
ระบบตอนนี้ไม่มีขั้นนี้เลย และเป็นขั้นที่ประหยัดเวลาผู้อนุมัติมากที่สุด

ต้องตรวจ:
- ใบลา — โควตาพอไหม ทับกับใบที่อนุมัติแล้วไหม ยื่นย้อนหลังเกินกำหนดไหม เป็นวันหยุดตามปฏิทินหรือเปล่า
- เบี้ยเลี้ยง — วันนั้นมีเช็คอินจริงไหม ชนใบลาที่อนุมัติแล้วไหม ไซต์มีอัตราหรือยัง
- แก้เช็คอิน — อยู่ในรอบที่ปิดไปแล้วหรือเปล่า

การตีกลับขั้นนี้ **ไม่ใช่การปฏิเสธ** ให้เป็นสถานะแยก "ตีกลับให้แก้ไข"
*ตรวจรับ* ยื่นใบลาที่โควตาไม่พอ → ตีกลับทันทีโดยไม่เข้าคิวหัวหน้า และบอกว่าขาดอีกกี่วัน

**APV-05 หน้าอนุมัติรวม แสดงเฉพาะที่ตัวเองมีอำนาจ**
- หัวหน้างาน — ใบลา แก้เช็คอิน วันชดเชย ของลูกทีม · **ไม่เห็นเบี้ยเลี้ยง**
- ฝ่ายบุคคล — **คิวอนุมัติมีเฉพาะเบี้ยเลี้ยงรายรอบ** บวกใบลาที่ตกมาแบบ fallback และคิว "รอตรวจสอบ"
- ฝ่ายบุคคล — **มุมมองอ่านอย่างเดียวของใบลาที่รออนุมัติ** ต้องแยกหน้าจอหรือแยกส่วนให้ชัดว่าไม่ใช่คิวงานของตัวเอง · ไม่มีปุ่มตัดสินใด ๆ และต้องไม่มีทั้งใน UI และใน API
- ฝ่ายบุคคล — โควตา ยอดคงเหลือ และประวัติการลาที่อนุมัติแล้วของทุกคน (สิทธิ์ผู้ดูแลข้อมูลบุคคล ไม่ใช่สิทธิ์ผู้อนุมัติ)
- **เอกสารสุขภาพและใบรับรองแพทย์** เปิดดูได้เฉพาะ **หัวหน้างานผู้อนุมัติใบนั้น** และ **ฝ่ายบุคคล** · ทุกครั้งที่เปิดต้องลง audit log ว่าใครเปิดเมื่อไหร่ · **ผู้บริหารและแอดมินไม่เปิด** แอดมินเห็นว่ามีไฟล์แนบและลบไม่ได้ แต่ไม่เปิดเนื้อหา · รายงานทุกชนิดแสดงแค่ "เอกสารครบ / ไม่ครบ"
- ผู้บริหาร — ทั้งหมด + เรื่องที่ขึ้นมาถึงตัวเอง
- แสดงจำนวนค้างเป็นตัวเลขตั้งแต่ยังไม่กดเข้า
- **เรียงตามความเร่งด่วน ไม่ใช่เวลาที่ยื่น** เรื่องที่ใกล้ถึงวันลาอยู่บนสุด

*ตรวจรับ* ล็อกอินเป็นหัวหน้างาน → ไม่พบรายการเบี้ยเลี้ยงของใครเลย ทั้งในหน้าจอและใน payload หลังบ้าน

**APV-06 ปฏิเสธต้องมีเหตุผล และแจ้งทันที**
ไม่ใช่เรื่องมารยาท แต่กระทบสถานะรายวันโดยตรง — ตาม CI-14 ถ้าใบลาถูกปฏิเสธก่อนถึงวันลาแต่พนักงานไม่รู้ แล้ววันนั้นไม่มาทำงาน เขาจะกลายเป็น **ขาดงาน** ทันที
- ปฏิเสธโดยไม่กรอกเหตุผลไม่ได้
- แจ้งทันทีที่กด ไม่ใช่รอให้เข้ามาดูเอง
- วันลาใกล้ถึง → เน้นการแจ้งเป็นพิเศษ
- ประเภทที่กฎหมายห้ามปฏิเสธ → **ไม่มีปุ่มปฏิเสธตั้งแต่แรก** เหลือแค่ปุ่มรับทราบ

### รอบ 2 — เส้นทางจริง

**APV-07 สถานะค้างและการเตือนซ้ำ**
ผู้บริหารเลือกไม่ให้ส่งต่ออัตโนมัติ ข้อดีคือไม่มีการเปลี่ยนคนอนุมัติโดยไม่มีใครรู้ ข้อแลกคือเรื่องอาจค้างนาน จึงต้องทำให้การค้าง**มองเห็นได้ชัด**
- เตือนซ้ำตามรอบที่ตั้งค่าได้ ค่าตั้งต้นแนะนำวันละครั้ง
- ใบลาใกล้ถึงวันลา → เตือนถี่ขึ้น + ขึ้นสีเตือน
- แสดงอายุของเรื่องเป็นจำนวนวันในทุกแถว
- **รายงานให้ผู้บริหารเห็นว่าใครมีเรื่องค้างกี่เรื่อง นานเท่าไหร่** — นี่คือทางที่ผู้บริหารเข้าไปแก้เอง แทนการให้ระบบส่งต่อ

*ตรวจรับ* ทิ้งเรื่องไว้ → ผู้อนุมัติได้รับเตือนซ้ำ และเรื่องต้องไม่ย้ายไปหาใครเองโดยเด็ดขาด

**APV-08 เพดานใบลาค้างและการคืนโควตา**
มาจากความขัดแย้งระหว่างสองการตัดสินใจ — BR-12 เดิมบอกว่าเลยวันลาแล้วให้ "ตกไป" คืนโควตาทันที แต่ APV-07 บอกให้คงค้างไว้

ทางออก: **คงค้างไว้ แต่มีเพดาน** เลยวันลาเกิน N วัน → ตกไป + คืนโควตา · **ค่าตั้งต้นแนะนำ 30 วัน ตั้งค่าได้**
- เหตุผล: ถ้าค้างตลอดไป โควตาถูกจองค้าง คนยื่นใบใหม่ไม่ได้ทั้งที่วันลายังเหลือ
- ตกไปต้องแจ้งทั้งผู้ยื่นและผู้อนุมัติ ไม่ใช่หายเงียบ
- แยกสถานะ "ตกไป" ออกจาก "ไม่อนุมัติ" ในรายงาน สาเหตุคนละเรื่อง

**APV-09 หน้าอนุมัติเบี้ยเลี้ยงรายรอบสำหรับฝ่ายบุคคล**
มองเป็นรอบ ไม่ใช่ทีละวันทีละคน
- รายชื่อทั้งหมดในรอบ + ยอดรวมแต่ละคน + จำนวนวันที่ติดปัญหา
- **รายการติดธงตาม CI-18 ขึ้นสีให้เห็นชัด พร้อมเหตุผลที่พนักงานกรอก** เพราะฝ่ายบุคคลไม่ได้อยู่หน้างาน ต้องใช้ข้อมูลนี้ตัดสินว่าจะไปถามหัวหน้าหรือไม่
- อนุมัติทั้งรอบของคนหนึ่ง หรือตัดบางวันออกพร้อมเหตุผล
- **ปุ่มปิดรอบกดไม่ได้จนกว่าจะไม่มีรายการค้าง** และต้องแสดงยอดรวมทั้งบริษัทให้ยืนยันก่อนกด
- ปิดรอบแล้วล็อก แก้ย้อนหลังไปเป็นรายการปรับปรุงรอบถัดไปตาม ALW-12

**APV-10 อนุมัติแก้เช็คอินข้ามวัน และวันชดเชย**
ทั้งคู่ไปที่หัวหน้างาน
- **แก้เช็คอิน** ต้องแสดง: ค่าเดิม · ค่าใหม่ · เบี้ยเลี้ยงเปลี่ยนกี่บาท · สถานะรายวันเปลี่ยนจากอะไรเป็นอะไร — ถ้าไม่บอก ผู้อนุมัติจะกดผ่านโดยไม่รู้ผลกระทบ
- **วันชดเชย** ต้องแสดง: ได้กี่วัน · หมดอายุเมื่อไหร่ · ปัจจุบันมีค้างอยู่เท่าไหร่
- ถ้าอยู่ในรอบที่ปิดแล้ว → เตือนว่าจะกลายเป็นรายการปรับปรุงรอบถัดไป

**APV-11 เรื่องที่ต้องขึ้นผู้บริหาร**
ห้าเรื่องนี้ปัจจุบันแอดมินทำได้เองโดยไม่มีใครเห็น ทั้งที่กระทบทั้งบริษัท — อัตราเบี้ยเลี้ยงรายไซต์ · ปฏิทินทั้งปี · สิทธิ์วันลารายคน · ยกเว้นเช็คอินรายบุคคล · เปลี่ยนบทบาทผู้ใช้

**สำคัญที่สุด: แยกสิทธิ์แก้ข้อมูล ออกจาก สิทธิ์อนุมัติ** แอดมินคือผู้ดูแลข้อมูล ไม่ใช่ผู้อนุมัติ ถ้าคนเดียวกันทำได้ทั้งสองอย่าง การอนุมัติก็ไม่มีความหมาย

*ตรวจรับ* แอดมินแก้อัตราเบี้ยเลี้ยง → ค่ายังไม่มีผลจนกว่าผู้บริหารอนุมัติ และระหว่างรอต้องแสดงว่าเป็นค่าที่รออนุมัติ

### รอบ 3 — ทำให้ใช้ได้จริง

**APV-12 อนุมัติหลายรายการพร้อมกันอย่างปลอดภัย**
- เลือกรวมได้ **เฉพาะรายการที่ไม่ติดธงและผ่านการตรวจอัตโนมัติแล้ว**
- รายการติดธงต้องกดทีละรายการ เลือกรวมไม่ได้
- ก่อนยืนยันสรุปให้เห็นว่ากี่รายการ รวมเงินเท่าไหร่
- **ปฏิเสธหลายรายการพร้อมกันไม่ได้** แต่ละรายการต้องมีเหตุผลของตัวเอง

**APV-13 บันทึกการอนุมัติที่ลบไม่ได้**
ใคร เมื่อไหร่ ตัดสินอะไร ด้วยเหตุผลอะไร และตอนนั้นเห็นข้อมูลชุดไหน
- ลบไม่ได้ แก้ไม่ได้ แม้แต่แอดมิน
- **เก็บสำเนาข้อมูลที่ผู้อนุมัติเห็น ณ เวลานั้น** เพราะข้อมูลต้นทางอาจถูกแก้ทีหลัง
- อนุมัติแทน = ระบุว่าแทนใครและเพราะอะไร
- เปิดดูเป็นเส้นเวลาตั้งแต่ยื่นจนจบ

**APV-14 แจ้งเตือนและใช้งานบนมือถือ**
หัวหน้างานอยู่หน้างาน ถ้าอนุมัติจากมือถือไม่ได้ เรื่องจะค้างจนกลับออฟฟิศ ซึ่งขัดกับการที่เลือกไม่ส่งต่ออัตโนมัติ
- ใช้ช่องทางเดียวกับ LV-10
- กดจากการแจ้งเตือน → เข้าเรื่องนั้นทันที ไม่ใช่ไปหน้าแรกแล้วหาเอง
- **การปฏิเสธบนมือถือต้องกรอกเหตุผลได้สะดวก** ไม่งั้นคนจะเลี่ยงไปกดอนุมัติแทน
